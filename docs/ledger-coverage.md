# 观测覆盖与历史记账本：验证、数据兼容及回滚

关联问题：#184、#163。此改动不安装插件、不改变 API key 或当前记账来源，不提升包版本。修复效果仍待问题报告者体验确认，关联PR不自动关闭issue。

## 行为与边界

- 余额快照不是流水。每日金额仅代表该记账本当日已有的观测/校正区间；主气泡、默认今日模块和自定义 `{expense_ds}` 内容都会显示「部分观测」，详情列出起止时间。无法观测的日期显示「未观测」，不替换成零消费或其它账户的金额。
- 北京时间跨日的相邻快照保留起止时间、起止余额和有正负号的净变化，显示在「跨日待归属净变化」中。它不计入任何一天、近7天或全部消费合计。净变化为零也可能同时存在充值和消费，不代表零消费。
- 当前日的旧快照、晚开始观测、历史日的提早停止，以及本版本检测到的同日长间隔（超过10分钟）会标注部分观测。未触发这一阈值也只叫「余额快照观测」，不会宣称完整账单。旧记录未保存同日间隔，不能据此恢复其全部离线时段。
- 「更多消费记录」中的记账本选择器只切换读取。密钥指纹不能证明实际账户身份；即使币种相同，也不把多个本的金额相加。旧版记录作为「旧版记录 · 未确认账户」单独查看。本机模型费用继续单列为本地估算，它没有账户归属证据。
- 已有「余额校正」仍只修改当前记账本的选定观测区间；它不能补齐跨日消费。跨日流水的人工分摊、不同密钥对应同一账户的确认/合并不在本次范围内。
- 每次报表最多展开3660个完全未观测日期，防止异常时间戳造成无限日期扩展；超长区间有明确提示，其完整端点及已有观测日期仍全部保留。

## 数据兼容

`accounting.version` 仍为1。新跨日观测只在该本的 `unassignedIntervals` 追加端点事实；同日行新增 `maxGapMs` 表示本版本看到的最长采样间隔。原有日期、消费、余额、校正日志、旧版历史不因查看而改变。

旧v1账本已保留每日最后余额与下一天起始余额。读取时可从这些现有端点推导跨日区间，并与新字段按起止时间去重；不重写历史日期、不修改过去的消费合计。没有端点的更早数据无法恢复。

## 无需安装的验证

在此源码目录运行：

```text
node --test tests/*.test.mjs
node tools/ci-audit.mjs --no-pack
node tools/z-layer-audit.mjs assets/whale-widget.js
node --check lib/index.js
node --check assets/whale-widget.js
```

测试直接导入 `lib/accounting.mjs`、`lib/usage-records.mjs`，使用内存合成账本和固定时钟；不读取真实 DSH/Codex 数据、不联网、不安装包。覆盖跨午夜/多日断档、净增/净减/净零、重复与倒序样本、旧v1记录、三把密钥、跨币种、未知日期、校正冲突及只读报表。UI接线测试在内存执行发布脚本的真实格式/渲染函数，验证主气泡和模板都消费覆盖标记、null不会变成0；另验证极端日期仍受展开上限约束。

经用户另行批准在测试 DSH 环境加载本源码后，重启宿主并硬刷新页面，可检查：

1. 打开「小鲸鱼记账 → 更多消费记录」，切换当前/历史/旧版记账本。各本金额及币种独立，切换后当前实际记账来源不变；看完旧本后新增的观测仍进入原来的当前本。
2. 检查两个午夜前后余额快照，例如23:59余额100、00:01余额90：区间显示净变化-10，起止时间正确；它不会被算作某天10元消费。之后当天90→85，只增加当天已观测消费5。
3. 有多天离线的合成数据应在每日列表显示「未观测」日期及跨日区间。图表和合计不把这些未知日期伪装成零消费数据点。
4. 晚开始观测、长时间停止刷新时，设置中的已观测消费与记录列表显示覆盖提示；旧版同日断档无法复原，不应解读为完整覆盖。
5. 仅查看报表前后比较合成账本，数据应不变。已有充值校正、重置和版本冲突保护仍正常；历史本没有新写入入口。

这些实机步骤尚未在本机执行，自动化测试通过不等于已经完成 DSH Desktop 实机验收。

## 回滚

源码回滚可撤销本次提交，或重新部署之前保留的源码版本，然后重启 DSH 宿主、硬刷新页面。不要用旧账本备份覆盖当前 `.dshw-usage.json`，否则会丢掉升级后新增的真实观测。

旧代码仍识别version1，并忽略新增 `unassignedIntervals` / `maxGapMs`；数据与校正继续保留。回滚后会失去本次新增的覆盖说明和历史本选择器。之后重新使用新代码，可再次从现存端点读取跨日净变化。
