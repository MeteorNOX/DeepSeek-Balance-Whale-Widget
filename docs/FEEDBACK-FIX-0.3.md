# v0.3 交互问题修复

## 问题与原因

1. **静止也闪动**：原生窗口监听将 Codex 子窗口的显示/隐藏当成主窗口生命周期；自身重显过程上报的暂时隐藏又可能触发下一轮恢复。
2. **指针/文本选择切换**：透明层在外部鼠标拖动经过角色时仍可能接管输入；菜单文本缺少禁止选择规则，光标写在整个 body 上。
3. **桌面/跟随切换菜单残留、错位、消失**：主进程先改窗口尺寸，而监督器尚未解除/重新建立原生跟随；相同模式也执行隐藏重显；界面在模式真正完成前就提示成功。
4. **工坊用法不清楚**：旧面板仅有导入/导出按钮，缺少适用包类型、操作步骤和导入后选择素材的位置。
5. **API 与会员展示混在一起**：旧版本只增加独立详情窗口，没有改变挂件主气泡的展示模式。

## 修复

- 限制原生生命周期事件来源；显示后留出稳定期，持续隐藏才有限恢复，避免自身恢复触发自身。
- 同模式点击不重映射；模式变更等待监督器确认 detach/attach 后完成，通知界面关闭菜单和清理选择。
- 全局鼠标按钮状态透传到输入层，外部拖动期间保持穿透；仅输入框可选择文本，光标按挂件交互状态控制。
- 工坊新增三步说明、格式限制、导入清单预览和导入后操作指引。
- 菜单顶部新增 API 额度/会员订阅额度切换；会员模式点击角色展示订阅卡片，API设置和汇率行隐藏。切换只保存展示偏好，不改变 Codex 登录、模型或密钥。
- 手感设置只通过菜单打开，切换桌面模式时不会留下展开的菜单。

## 验证

- 新增自动回归覆盖恢复自激、持续隐藏、相同模式、原生切换确认、模式保存失败和输入归属。
- 真实监督器与 Electron 完成16次模式切换，重复选择当前模式不增加重显计数。
- 30秒静止观测中保持可见，重显计数未增加。
- 真实界面验证会员卡片、API配置不变、菜单关闭/取消文字选择、外部拖动穿透以及工坊说明。
- 实机验证仍需用户按原录屏场景复验；未把合成测试称作真实订阅额度或Mac实机验证。

## 使用

模式切换现在原位更新并保留菜单打开状态。订阅模式完成或取消后的提示只显示本机观测 token，不显示 API 金额；未打开额度卡片时也有中性提示。5 小时额度与每周额度按官方窗口时长分别标注，各自保留重置时间。本机滚动 token 统计不等于官方剩余额度。

菜单区域同步除属性变化外，增加监听菜单与卡片自身尺寸变化，覆盖字体加载、flex 布局等不触发窗口 resize 的情况。测试验证仅修改样式导致菜单尺寸变化时，原生区域仍包含完整菜单。用户偶发菜单裁切尚待实际使用复验。

控制面板顶部固定显示 **API 余额 / Codex 订阅**。选择 Codex 订阅后，点击 **查看订阅额度 →**；无需寻找隐藏入口。仅切换展示，不切换登录或修改 API。菜单按“外观与位置、声音与气泡、用量与资源”分组，空间不足时滚动内容区，顶部切换保持可见。

订阅入口缺失来自初始化顺序：模式模块在菜单创建前查询 DOM，没有挂载按钮。现在等页面完成初始化后挂载。API 设置与消费记录统一为不透明卡片，移除整屏灰色遮罩和背景模糊，保留原生窗口区域限制。菜单优先避开边缘、向可用方向展开，不移动角色；设置窗口固定标题与保存按钮。

菜单顶部选 **API 余额** 或 **Codex 订阅**，再点击角色查看对应数据。会员账号没有新额度快照时会说明不可用；不把百分比换算为固定剩余token。

工坊：先在角色/音效/资源管理中添加素材 → 导出JSON分享。使用他人包时选择文件 → 检查清单 → 导入 → 重新加载素材列表 → 到角色/音效下拉或气泡图库选用。不是安装DSH ZIP或EXE。

## 真实环境补充定位

实际日志确认另一直接原因：旧逻辑将超过6秒的监督器心跳延迟当作宿主消失，主动隐藏窗口，随后又重显。现已将健康状态和可见性命令分离：延迟只记录状态，不改变窗口；真正的宿主退出消息或启动时记录的监督器进程确已退出才关闭。进程路径查询改为轻量系统API，并只对目标窗口查询DWM状态。拖动输入拒绝迟到的鼠标按键快照。

退出时迟到IPC会先校验窗口/渲染器是否仍存在，避免Object has been destroyed异常。Windows GUI标准输入EOF不再被当成监督器死亡证据。验收以不出现非预期隐藏为目标，而不是恢复次数。
## 透明窗口覆盖范围修复

再次复发时确认：角色区域有效、宿主与挂件原生可见、无隐藏/重启记录；准备截图后画面重新出现。Windows挂件现默认采用软件合成，移除强制GPU光栅化，作为可回滚的透明窗口兼容措施；仅改变挂件自己的Electron进程，macOS与Codex本体不变。不能据此断言GPU是所有消失现象的唯一原因。隔离实机测试在不抬高窗口、不调用capturePage重绘的采样阶段连续12次屏幕像素匹配通过，无空闲重绘循环。

鼠标复发另有明确代码原因：旧命中检测把任意打开的dialog和整屏mask当作整窗交互区域。现在只允许实际卡片、控件和角色不透明区域接收鼠标，透明背景穿透；新增打开设置和记录窗口时的透明角落命中测试。视口缩小时直接提交合法位置，不再动画经过屏幕外的坐标。

后续用户反馈任务结束附近偶发不可见，但现场检查时进程/页面均在运行，恢复与重显计数为零。尚未确定每次消失的唯一原因。区域变化后现在提交一次现有帧重绘，避免等待下一次交互才刷新；同时监听角色自身尺寸与素材加载。该逻辑不隐藏窗口、不重载页面、无定时重绘。六轮消费气泡弹出/收起验证角色区域持续保留，重显次数不增加。显示/隐藏事件保留最多24条本机状态记录，供复发时区分宿主隐藏与绘制问题。

同机对照：暂停小鲸鱼后，用户反馈正文短暂白块和光标切换都暂时消失。原透明窗口虽然大部分像素不可见，但原生边界覆盖整个Codex客户区。

Windows现在使用原生窗口region，只包含鲸鱼、气泡、展开的菜单和设置卡片。空白客户区不属于挂件窗口，不接收它的绘制或鼠标命中；对话框只包含卡片，不纳入整屏遮罩。区域只在实际几何变化时提交，窗口resize保留旧的有效区域直到新布局上报，不反复清空导致消失。Mac不调用不支持的setShape接口。

真实Windows区域探针已确认：空白正文测试点位于region之外，鲸鱼测试点位于region之内；UI功能回归通过。白块是否在用户实际绘制环境完全消失，仍按安装后同机场景验收。

启动竞争条件也已修正：页面加载期间的显示命令不再安排重新加载；页面就绪会取消待执行的恢复，恢复计时器执行前再次检查就绪状态，子框架加载失败不再触发整页恢复。重复显示、加载完成与恢复计时器竞争均有回归测试。

安装验证要求实际服务的构建版本匹配且渲染器已就绪。此前主动暂停的状态会保留；如因此不能启动，安装器明确报告未验证，不会把任务注册成功当作挂件运行成功。需主动打开挂件后重试安装验证。
