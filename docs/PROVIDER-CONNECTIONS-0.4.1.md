# v0.4.1 本地测试版：余额连接与自定义协议

> 本文记录初始连接模块和高级字段。当前 fixed 已更新自动检测及确认入口，自动模式行为以 [fixed 说明](AUTO-PROBE-FIXED.md) 为准。

此版本用于本地测试，构建标识为 `provider-connections-20261005`，分发名称为 `Codex-v0.4.1`。它尚未发布到远端。v0.4.0 的 Release、标签、测试数量和旧验收记录仍属于历史版本，不能作为本构建已经完成验收的证明。

本次修复把“读取哪份 Codex 配置”和“使用哪套余额接口”分开。每个命名连接保存自己的地址、环境变量引用、余额协议和金额口径，防止切换 provider/profile 后沿用另一个服务的 URL 或密钥。项目 TOML 局部配置按表递归合并；找不到 provider 时明确报错，不再回退到其他服务商。

## 默认使用与状态含义

没有配置命名连接时，默认继续读取已配置的 Codex 来源并自动探测已实现的常见协议。普通使用无需展开高级请求规则。新增命名连接从“不查询余额”开始，填写完接口后再预览、确认。

自动模式已实现兼容账单、兼容密钥额度及 DeepSeek 原生余额的识别路径。它没有覆盖所有兼容站点，也没有验证任意域名都提供可用余额接口；“OpenAI-compatible”通常只说明模型请求格式兼容，不能证明余额字段或单位兼容。官方 OpenAI 的自动模式不调用未经验证的余额端点。

| 显示状态 | 含义与后续操作 |
| --- | --- |
| 账户余额 | 已确认的账户金额口径；仍须以服务商账单为准。 |
| 密钥剩余额度 | 当前 API 密钥可用额度，可能受密钥限额影响，不代表账户总资金。 |
| 不限额 | 接口明确返回匹配的不限额标记；不把巨大数字自动认定为不限额，也不把密钥不限额当作账户无限资金。 |
| 字段与单位尚未确认 | 自动探测取得候选金额，但不能据此记账或产生账户消费通知。打开设置预览，选择具体协议并核对单位、币种和范围。 |
| 不支持余额查询 | 连接选择了 `none`，或没有受支持的余额协议；保留本机 token、任务记录及已配置价格的估算能力。 |
| 查询失败 | 显示认证、网络、响应形状等错误类别；未知值不作为零余额。 |

自动模式通常保持待确认。例外是代码已识别的官方 DeepSeek 标准余额端点、标准单位和默认余额系数；其他站点即使返回同样字段，也不因此获得自动记账资格。选择 `auto` 后不能仅靠勾选确认绕过这个限制；需要选择具体接口。

## 跟随来源与固定连接

设置中的“余额连接”支持两种模式：

- **跟随 Codex 配置（`follow`）**：按 provider ID 和 profile 精确匹配已保存连接。无 profile 时填空字符串；同一来源不能同时匹配多个连接。未匹配时使用当前来源的原有余额设置。填写了 API 基准地址的连接，必须与读取到的来源地址一致，路径也参与校验。
- **固定连接（`fixed`）**：明确选择一个命名连接，始终使用它自己的地址和认证，不混入当前 Codex provider 的密钥或请求头。须填写 API 基准地址；使用余额专用认证或无认证时，不要求另填推理 API 密钥。

“跟随”仅指实际读取到的 Codex 配置文件及已选择的 profile；目前不能还原未读取到的 CLI 临时覆盖或保证等于当前聊天的最终有效配置。界面会说明“仅已读取的 Codex 配置；不含 CLI 临时覆盖”。它与挂件窗口的“跟随 Codex / 独立桌面”位置模式是两项设置。

命名连接中的 `keyEnv` 是环境变量名称，不是密钥值。跟随连接若显式指定专用 `keyEnv`，或者在相对余额路径中使用环境变量认证/参数，必须填写 API 基准地址以绑定来源。只继承当前可信 provider 的认证时，可以不覆盖它的地址。

全局可信 provider 中合法的 `http_headers`、`env_http_headers` 可用于同源继承认证。项目配置不能自行更换目的域名或租户路径、添加秘密环境变量引用或改写鉴权请求头；需要在挂件连接中明确绑定自己的地址和认证。显式指定新密钥时不会继续继承旧 provider 的 Authorization 请求头。

## 配置、预览和确认

1. 打开鲸鱼菜单的设置，在“余额连接”选择跟随或固定模式。可先预览当前配置，判断是否已有可识别的接口。
2. 选择“新建连接”，或选中已有连接后点击“载入规则”。已有 URL、环境变量引用和规则默认隐藏，只有显式载入才展开；真实密钥始终不返回编辑器。
3. 填写名称、来源匹配条件或固定地址，选择具体余额接口。凭据填写环境变量名称，例如 `WALLET_BALANCE_KEY`；变量须存在于运行挂件的进程环境中。
4. 按服务商文档填写余额 URL、认证、币种及金额范围。仅当内置协议不适用时选择“自定义 JSON”，按需展开高级规则。
5. 点击预览，核对候选余额、累计消耗、币种和范围。确认正确后勾选确认并保存。修改请求、字段、单位或认证后，需要重新预览确认。

预览会向所配置的余额接口发送请求，但不保存草稿、不写账本、不更新正式自动识别缓存，也不触发账户消费通知。预览只返回经过筛选的金额与协议摘要，不返回原始响应体、解析后的密钥或请求认证值。预览成功说明本次请求能解析，不能单凭它证明字段代表账户资金，仍应对照接口说明和服务商页面。

删除当前固定连接前，先切换到另一连接或保存为跟随模式。连接编辑按字段合并；高级规则中的请求头、查询参数和请求体按整项替换，因此把对应映射清空为 `{}` 可以移除旧参数。

## 已实现协议与单位

| `adapter` | 默认请求规则 | 金额含义与基础换算 |
| --- | --- | --- |
| `auto` | 官方 DeepSeek 使用原生余额；其他服务先尝试兼容账单，遇到指定的不支持/形状错误时尝试密钥额度。认证失败不继续试其他协议。 | 普通兼容服务的候选字段与单位待确认。 |
| `billing` | API 基准或请求 URL 作为目录，追加 `dashboard/billing/subscription` 与 `dashboard/billing/usage`。 | `hard_limit_usd` 是美元总额度；`total_usage` 默认是美分，先除以 100，再应用消耗系数。剩余额度由总额度减累计消耗得到。 |
| `newapi` | 未填请求 URL 时，去掉基准路径末尾的 `/v1` 等版本段，追加 `api/usage/token`；已填则使用指定接口。 | `total_available` / `total_used` 作为金额；`remain_quota` / `used_quota` 先除以 500000，再应用各自系数。范围固定为密钥额度。 |
| `deepseek` | 未填请求 URL 时，去掉末尾版本段后追加 `user/balance`；已填则使用指定接口。 | 从 `balance_infos` 选择币种，读取 `total_balance` 并乘余额系数；币种以响应为准。 |
| `custom-json` | 必须明确填写请求 URL 或路径。 | 按所选字段读取数值，分别乘余额/消耗系数；范围由用户指定并确认。 |
| `none` | 不发送余额请求。 | 不产生新的余额差分消费；用量及任务记录功能继续保留。 |

内置换算已经包含表中的基础单位。例如 NewAPI 的原始 quota 默认已经除以 500000，通常不应再把余额系数设置为 `1/500000`；兼容账单的消耗也不应再次除以 100。服务商若采用不同协议，需按其文档设置额外系数或使用自定义映射。改变币种名称本身不会执行汇率换算。

默认路径保留租户前缀。例如基准 `https://gateway.example.test/tenant/a/v1` 的 NewAPI 默认路径为 `/tenant/a/api/usage/token`；如果实际服务把接口放在根目录，应明确填写 `/api/usage/token`。`billing` 的请求 URL 是账单目录，不应把某个最终 `subscription` URL 填成目录。

## 高级请求规则

支持 GET 或 POST JSON、Bearer/自定义请求头/同源继承/无认证，以及结构化请求头和查询参数。

| 字段 | 约束 |
| --- | --- |
| `request.url` | 完整 HTTPS URL、同源绝对路径或相对基准路径；本机回环地址可用 HTTP。新连接 URL 不放查询参数，改用 `query` / `envQuery`。 |
| `request.method` / `body` | `GET` 无请求体；`POST` 可发送 JSON，请求体不放凭据。 |
| `request.auth.type` | `inherit`、`bearer`、`header` 或 `none`。`bearer` / `header` 通过 `keyEnv` 取秘密；`header` 另填头名称。 |
| `headers` / `query` | 非秘密固定参数。认证和秘密参数使用环境变量引用，不粘贴真实值。 |
| `envHeaders` / `envQuery` | 参数名映射到环境变量名称。 |
| `mapping.balanceField` / `usedField` | 点分隔 JSON 字段路径；不支持执行表达式。金额须为有效数值或数值字符串，空数组、布尔值、空字符串不当作零。 |
| `mapping.unlimitedField` / `unlimitedValue` | 明确指定不限额字段与匹配值，按类型严格匹配；没有协议依据时不把 `1`、`-1` 或巨大数字猜成不限额。 |
| `mapping.scope` | `account`、`api-key-quota` 或 `custom`；内置协议有确定范围时使用内置范围。 |
| `mapping.currency` / `balanceScale` / `usedScale` | 三位大写币种、余额系数、累计消耗系数。 |
| `mapping.confirmed` | 用户已核对请求与金额口径；默认 `false`。自动模式的普通候选仍待选择具体协议。 |

跨域余额 URL 必须显式使用专用 Bearer 或请求头认证，并指定其环境变量名称；不能跨域继承推理 API 密钥，也不允许附带环境变量请求头/查询参数绕过这一限制。重定向被拒绝，请直接配置最终接口。协议仍受请求大小、响应大小、字段白名单和危险请求头限制。

以下仅演示结构，域名和环境变量名称均为占位示例。它是更新本地设置的 patch 格式，不是已经可用的接口：

```json
{
  "connectionMode": "fixed",
  "selectedConnection": "wallet-demo",
  "connectionUpdate": {
    "id": "wallet-demo",
    "value": {
      "name": "我的余额连接",
      "match": { "providerId": "", "profile": "" },
      "baseUrl": "https://api.example.test/v1",
      "keyEnv": "",
      "balance": {
        "adapter": "custom-json",
        "request": {
          "url": "https://billing.example.test/wallet",
          "method": "GET",
          "auth": { "type": "bearer", "keyEnv": "WALLET_BALANCE_KEY", "header": "" },
          "headers": {},
          "envHeaders": {},
          "query": {},
          "envQuery": {},
          "body": null
        },
        "mapping": {
          "balanceField": "wallet.remaining",
          "usedField": "wallet.spent",
          "unlimitedField": "",
          "unlimitedValue": true,
          "scope": "account",
          "currency": "USD",
          "balanceScale": 1,
          "usedScale": 1,
          "confirmed": false
        }
      }
    }
  }
}
```

常规使用通过设置编辑器完成，不需要手改数据文件。开发接口中，`POST /api/balance-preview` 接收 `{ "patch": ... }`；`PUT /api/config` 保存 patch；`GET /api/connections/:id` 仅用于显式载入可编辑配置。普通设置查询只返回连接名称、接口类型和配置状态等摘要。连接 ID 保持稳定；最多保存 64 个连接。

## 旧设置迁移、历史与回滚

没有旧手动地址或密钥覆盖时，可继续从 Codex 配置解析来源。若原有 `baseUrl` / `keyEnv` 覆盖没有来源绑定，新版会提示确认，避免它在 provider/profile 改变后漂移。

有两种迁移方式：

1. 在设置的“旧版接口与 Codex 配置来源”中，确认当前读取的来源，重新填写属于同一服务的 API 地址与密钥环境变量名称并保存。旧覆盖未绑定来源时必须同时确认两项，明确清除也可提交空值；如要取消覆盖，使用对应清除操作，不要把空白输入误当成删除。保存无关选项不会自动确认或迁移旧凭据。
2. 新建命名连接，填写独立地址和认证，切换到固定模式，预览并确认。它使用完整的新连接，不再受旧根设置的余额地址和密钥覆盖影响。

切换 provider/profile 后，旧覆盖若不再匹配来源，会明确报错；重新确认，或切换到对应命名连接即可。新连接、新凭据或新的金额口径先建立观测基准，不把不同接口的金额直接相减。

已有历史不重新计算，也不自动清洗过去错误口径留下的金额。保留旧历史入口；不能将本次修复描述为已校正服务商历史账单。第一次有效新样本只建立基准，后续同口径增量才可能进入消费通知。

安装测试版前保留旧版本和完整安装器生成的私有回执。需要回滚时，使用**此次测试版安装对应、恢复目标经核验为旧版的专用回执**及其 `recovery-scripts/rollback-package.ps1`；先运行 `-Receipt <installation.json> -CheckOnly` 查看恢复版本，再按同一回执执行。不凭目录名猜备份，也不拿其他安装的回执代替。未实际安装测试版时，不需要执行安装回滚。

回滚恢复程序及启动配置，保留最新设置、素材和账本；旧程序不理解新的命名连接，可能重新使用旧根设置，因此回滚后须核对旧版实际连接。不要通过删除账本或改写历史金额来回滚。回执含私人运行信息，不随反馈或发行包上传。macOS 使用其对应安装回执与回滚流程，见 [macOS 文档](MACOS.md)。

## 本地验收指南

先核对状态版本为 `0.4.1`、构建为 `provider-connections-20261005`。使用隔离的合成配置/余额响应验证安全边界；真实服务只按你已授权的余额接口测试，不要向公开反馈附上密钥、真实地址、个人路径或原始响应。

- 跟随模式分别匹配两个 provider/profile，确认切换整套连接；项目仅改模型时，不丢失原 provider 和凭据。未知 provider 应报配置错误。
- 固定连接在当前 Codex provider 变化后保持自己的地址和认证。仅有余额专用凭据也能请求，不要求借用推理密钥。
- 使用 `auto` 的普通兼容响应只显示待确认状态；切换具体协议、预览并确认后，首个正式样本不产生历史消费通知。
- 用合成数据先返回一套账单字段，再切换到另一协议或单位。切换当次应为 **0 笔虚假新增消费**，随后相同计量口径的真实增量正常累计。不限额、未知字段和不支持余额也不能制造巨额消费。
- 预览前后正式账本、账户消费通知及保存的设置不变；预览结果不包含 raw 响应、认证头、真实密钥或完整私密配置。保存失败也不覆盖原设置。
- 选择 `none` 后不查询余额，本机 token、任务结束状态和既有历史仍可查看。
- 账户金额、密钥额度和不限额文字保持对应含义。主界面金额保留两位小数，小额正值继续累计；设置预览可以保留核对单位所需的精度。
- 检查长连接名、巨大候选数字、错误文字、窄屏及缩放时的布局：设置可滚动，按钮可见；正式气泡文字位于安全区域内，没有裁切、遮挡或被旧“余额”标签误导。

相关合成回归可在源码目录运行：

```powershell
node --test tests/provider-connections-config.test.mjs tests/balance-protocol.test.mjs tests/provider-meter-service.test.mjs tests/connection-settings-ui.test.mjs tests/balance-view-ui.test.mjs
```

该命令是复核入口，不代表本构建已完成所有自动测试、真实账户或桌面平台验收。最终以本次验证记录及实际测试结果为准；Windows 结果不能替代 macOS 实机结果。
