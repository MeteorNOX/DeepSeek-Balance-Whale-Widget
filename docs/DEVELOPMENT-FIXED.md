# Codex-v0.4(fixed)：开发过程与能力摘要

本文总结项目开发讨论形成的最终决定、累计功能和本轮修复，不复制原始聊天、私人配置、真实服务地址、个人路径、凭据或测试现场。对外包名为 `Codex-v0.4(fixed)`，内部版本 `0.4.1`，构建标识 `auto-probe-fixed-20261005`；发行标签 `codex-v0.4.0(fixed)`。

## 从原挂件到 Codex 桌面适配

起点是在 Codex 环境中保留小鲸鱼角色、声音、气泡和拖动交互，并读取 API 余额。实现逐步形成独立 Electron 透明工具窗口、Windows 原生跟随、GUI 启动器、本地 IPC、安装备份和回滚；不向 Codex 主页面或主输入框注入 DSH 的 DOM 逻辑。

后续增加“概览 / 用量 / 设置”页面、API/订阅显示模式、跟随 Codex/独立桌面模式、本地素材工坊、角色与音效管理、预算与预警、图表和历史账户入口。窗口跟随模式与余额连接跟随模式是两项独立设置。

macOS 兼容来自 [1llysviel 的 PR #128](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget/pull/128)，保留平台实现和署名；Windows 后续修复不代表 Mac 实机已经验收。来源与许可见 [署名说明](ATTRIBUTION.md)。

## 计量、任务状态与账户反馈的分离

开发中持续保留三条边界：关闭挂件只停止观察，不会停止 Codex 请求；失败或取消仍可能计费；本机会话 token 不等于官方订阅剩余额度。

最初将余额变化用于任务提示，但并行任务暴露了归属问题：同一个 key 的区间扣费可能来自其他聊天、设备或延迟入账，不能全算给某一轮。后续把账户新增消费、每轮状态与 token、按模型价格估算的轮次费用分开。首次有效样本建立基准，后续新增批次持久化并去重；暂停展示时合并累计，恢复后再展示。

账本保留原币种，汇率仅用于显示。金额内部保留精度，界面按显示规则呈现。跨午夜、中断恢复、任务去重和旧账户入口已有实现，但没有精确逐日拆账、服务商完整流水还原或退款净额账本；这些限制没有因 fixed 升级而消失。

## 桌面反馈与交互取舍

“挂件消失”被拆成窗口隐藏、软件合成、绘制区域和层级等不同问题，分别修复，而不是通过周期性重启掩盖。人物缩放、按压回弹和连续点击又推动命中轮廓、输入路由与原生窗口区域保持一致；透明区仍穿透。

位置记忆改为持久化用户位置意图，避免启动动画、临时缩窗或无关设置保存覆盖它。拖动取消、失焦和捕获丢失不提交无效坐标。气泡队列、图片回退、截止时间和旧异步回调采用一致生命周期；长文与图文使用通用安全区布局。

全局空白点击关闭曾经试作，随后主动撤回。底层软件的正常点击不能一概视为用户已经读完提示，因此继续采用明确关闭、人物交互和提示自身超时；不是忘记完成 #177。详见 [空白点击决定](OUTSIDE-CLICK-DECISION.md)。

## 初期 0.4.1：先隔离连接与认证

多 provider、自定义中转与账单域名的反馈推动了命名余额连接：跟随实际读取的 Codex provider/profile，或固定选择独立连接。配置表递归合并；未知 provider 明确失败；地址、租户路径、认证头和环境变量引用受来源绑定约束。旧地址与密钥覆盖不能随 provider 切换而漂移。

高级请求支持完整/相对 URL、GET/POST JSON、同源继承或专用认证、结构化头与参数。秘密通过受支持的环境变量引用获取，不把实际值保存到普通设置。预览不落账，正式口径变化先建立新计量基准。#190 因此已部分覆盖 POST/body 能力，不能再用旧版“只支持 GET”的结论描述当前包。

这一阶段采用了过于保守的自动模式：普通第三方结果即使有可识别字段，也普遍停留在未确认；普通界面又缺少直接采用候选的入口。查询能够成功，但用户仍难以完成配置。该历史行为记录在 [初期连接模块说明](PROVIDER-CONNECTIONS-0.4.1.md)，其中旧自动规则、换算表与测试数字不作为 fixed 的当前规则。

## fixed：有依据的自动识别与直接确认

本轮读取公开源码、官方 API 文档和 SDK，先核对范围与单位，再实现有界顺序探测。关键发现包括：OneAPI/NewAPI/Veloera 的兼容账单可能用 `100000000` 表示不限额；NewAPI 原生 `total_*` 是整数 quota；`credit_summary.total_used=0` 是占位值；OneHub 相同账单形状可能在账户与 key 之间换范围；OpenRouter 管理 credits 与普通 key 限额不是同一接口。

最终流程是：有界尝试已知同源路径及尾斜杠别名，校验完整契约，可信命中直接使用；有完整可核对规则的候选提供“确认并使用”；仍缺少真实单位或字段依据时不给虚假的确认捷径，保留高级配置。注册表的十三项包含别名、双请求账单、匿名单位元数据和管理接口条件，并非十三个品牌逐一实测。

原生 quota 在自动与显式选择中都先验证安全整数和加总关系，再按实际单位或已确认系数换算。不限额不显示巨额有限资金；占位使用量不作为累计消费。已识别或已配置的协议、字段、单位、范围或计数器周期变化时更换计量基准，避免两个不同指标相减；服务商未声明的口径变化仍可能需要用户核对。

常规刷新缓存的是命中/候选请求计划与单位元数据，不缓存敏感响应体或候选金额；明确未命中短暂缓存。权限问题允许继续核查其它受支持只读接口，网络和服务端故障保留为重试状态，限流中止并退避。预览与实时查询有独立识别缓存，但共用限流退避。

候选采用入口使用绑定草稿、当前配置与来源的限时单次证明，防止迟到预览、旧窗口和切换来源后误保存。普通用户可完成检测、核对、采用与重载，不必先填写 JSON。技术细节见 [自动检测说明](AUTO-PROBE-FIXED.md) 和 [协议公开来源](BALANCE-PROTOCOL-SOURCES.md)。

## 验证证据与交付状态

本轮构建记录为 **482 项自动测试通过、9 项隐私门禁通过**。真实 Electron 使用隔离合成服务完成 **6 组流程、7 个布局样本和 8 张截图**，渲染错误为零。覆盖普通自动验证、候选采用、独立认证 POST、来源/单位变化、迟到或过期结果、连接管理和金额语义布局。

本机真实查询已确认能够正常返回候选结果（candidate）；这一结果只证明本次查询和候选通路可用，不等于用户已证明所有字段假设，更不是所有中转站或 Mac 的全量验收。真实账号、其它平台与长期运行边界继续列在 [已知问题](KNOWN-ISSUES-FIXED.md)。

历史 **341** 项自动测试、**120** 次角色边缘连击、**18** 次透明区对照、**52** 个通用布局场景属于此前相应实现的基线，本轮没有重新宣称执行，也不与当前数字相加。早期 0.4.1 的测试记录同样留在其专题文档中，不取代 fixed 验证记录。

对外 fixed 名称与内部 `0.4.1` 可以同时存在；区分初期连接构建与本包时必须核对 build。安装/回滚使用本次私有回执对应的备份，不凭版本号猜测；回滚程序不等于删除新增账本或素材。成品与源码通过发布清单绑定，远端状态以 GitHub Release 为准。
