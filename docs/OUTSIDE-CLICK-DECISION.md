# v0.3(fixed) 空白点击设计决定

**本版不采用全局“点击组件外空白处就统一关闭”的交互。** 曾试作的 Windows/macOS 全局点击监听、消息转发与自动关闭逻辑已撤回；保留各控件内原有关闭入口、人物点击交互及已有超时规则。气泡动画和菜单悬停修复不会重新引入全局空白点击关闭。

## 建议的原意

[Issue #177：二级菜单和人物气泡无法点击空白区域关闭](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget/issues/177) 针对 macOS 的 For-Codex 版本提出：菜单、弹层、人物气泡或账户卡片打开后，点击组件外空白处将其关闭，并恢复透明区域点击穿透。

这是常见且合理的弹层交互预期，能够减少寻找关闭入口的操作。本决定不是认定该建议错误，也不是判断提交者的实现质量；它说明的是当前桌面挂件希望保留哪种行为。

## 为什么本挂件选择不采用

### 宿主空白处也是正常工作区域

挂件覆盖在 Codex 或其他软件上。对挂件而言的“透明空白”，可能正是用户要输入文字、选择内容、拖动窗口或切换任务的位置。这些点击属于底层软件的正常工作，不必然表示用户已经阅读或希望关闭挂件内容。

如果把任何外部点击都视为关闭指令，用户在继续工作时可能误清尚未阅读的人物气泡、任务提示或本轮消耗提示。对需要稍后查看的信息，本版优先保留明确关闭和已有超时的语义。

### 二级菜单的关闭边界需要单独定义

“组件外”不是一个天然一致的范围。角色/音效列表、设置卡片、账户卡片和消费记录可能位于主菜单外；人物与菜单按钮之间又有透明缝隙。仅检查主菜单矩形，会把操作子面板误认为外部点击；把全部面板合并为一个关闭范围，又需要明确关闭哪一级、是否保留父菜单以及提示是否一并清除。

这些问题可以通过进一步设计解决，但它们不应被一个覆盖全部菜单、卡片和提示的全局关闭规则隐式决定。当前继续使用各控件已有的明确交互。

### 点击穿透与全局观察是不同职责

透明区域需要让底层软件正常收到鼠标操作。挂件自身无法仅依赖普通 DOM 外部点击事件，观察已经穿透给其他原生窗口的所有点击；若要跨窗口统一关闭，还需额外的全局鼠标观察或平台级事件机制。

这类机制在技术上可以实现，但会增加 Windows/macOS 的监听注册与清理、窗口坐标、模式切换、拖动按键、启动退出及事件时序维护。为隐藏弹层而保留这一套全局生命周期，对本版预期收益并不划算。撤回相关监听后，底层点击穿透和挂件内部交互继续各自处理。

## 当前明确保留的行为

- 点击各控件已有的关闭入口，按该控件自身规则关闭。
- 人物点击继续执行既有气泡或账户信息交互；不统一改变为一个新的全局关闭动作。
- 已有自动超时继续生效，关闭时保留完整淡出。
- 人物到菜单按钮的有限悬停范围只维持按钮可达，不增加可点击面积。
- 菜单打开时维持按钮可见；“隐藏菜单按钮”设置仍优先。
- 在 Codex 正文、输入框或其他软件点击、拖选，透明区域继续穿透；不会由新增加的全局外部点击规则统一清空挂件内容。

这里的“不采用”针对全局外部点击关闭，不表示删除各控件内部原本存在的关闭、切换或取消行为。具体操作按 [用户测试清单](USER_TEST_CHECKLIST.md) 验收。

## 范围与后续

本决定适用于 **v0.3(fixed)**，构建 `0.3.0+codex.20260929173027`。本次已获用户授权的 `For-Codex` 发布使用标签 `codex-v0.3.0-fixed.2`，Release 名称为 `Codex-v0.3(fixed)`，不改变此项设计决定。它是主动撤回试作后的产品选择，不是跨平台技术不可行的结论，也不代表 Issue #177 已关闭或相关 PR 已合并。

以后若有清楚的使用需求，可以分别讨论仅关闭某一级菜单、用户可选行为或提示保留规则；任何后续方案仍需同时验证底层穿透、未读提示、子面板与两平台生命周期。本版不包含这些未来方案。

macOS 继续保留 [PR #128](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget/pull/128) 的实现、来源和贡献者 [1llysviel](https://github.com/1llysviel) 署名；撤回新增全局点击监听不等于撤回原有 Mac 支持。Mac 实机验收仍待完成。
